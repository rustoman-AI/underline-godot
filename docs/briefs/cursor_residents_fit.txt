CURSOR: RESIDENT FIGURES V2, FIT AND STAGE (no install yet)
New resident art is being drawn by hand, one image at a time, in incoming-art/residents_v2/{pilot,batch1,batch2,...}/<stem>.png (1000x3000 transparent PNG, standing figure about 2400 px, facing right, one figure per file). Accepted so far: body_01, body_02, workshop_01 (pilot), body_03..08 (batch1), body_09..12, workshop_02, workshop_03 (batch2). More batches come. Local only. No push. You are NOT allowed to run any pose generator or anything that composes poses from other poses (the old rejected approach). What you build here is a deterministic FIT tool: it trims, scales and aligns an existing image, it draws nothing.

1. FIT TOOL (.tools/fit_residents.gd or .ps1, your choice)
For every accepted stem, produce the game sprite: canvas 212x660 (the size of the current assets/figures/poses/*.webp), RGBA WebP, quality as the existing files. Scale so the standing height of the figure body (head top to soles, ignoring props that reach below the soles such as a cane, a dangling bag or a tool) lands in 540 to 600 px, keeping each person's relative height (the source heights differ by up to 8%, preserve that). Feet baseline at y = 636. Horizontally centre on the torso, not on the prop. Use the resampling that keeps the ink outline crisp (Lanczos or area, then check the outline is not eaten). Keep a 2 px transparent edge. Write to incoming-art/residents_v2/game/<stem>.webp and print the table stem / source px / scaled px / baseline fix / any warning.
2. SEATED POSES (infirmary_02 when it arrives) use seated height about 78% of the standing height on the same baseline; the tool takes a per-stem override file.
3. PALETTES. The game also loads palettes from assets/figures/poses/palettes/<name>/<stem>.webp (currently drab, ochre and others). Produce deterministic recolours of each accepted figure for those palette names: hue and lightness shifts on clothing only, keep skin, hair, outline and the accent where possible, never darker than the mid-value rule (clothes must not drop near black). Keep the same palette names, write to incoming-art/residents_v2/game/palettes/<name>/<stem>.webp. If the existing palette folders were made with a script, reuse its parameters only if they respect the mid-value rule; otherwise define new ones and document them in the tool header.
4. REVIEW. Make a review scene or sheet (extend the existing worker-tint shots) that draws each fitted figure on the station wall at the game scale and at 0.5x, with the current tint (variant A in _paint_sprite) so we see what the player sees. Also run one station screenshot with all accepted new figures in the rooms, 1280x720 and 1920x1080. Save under shots/residents_v2/.
5. DO NOT install into assets/figures/poses yet. The old body_01..12 and air_filter_01 stay until the whole set is accepted. Report: the table, any figure that fails the baseline or height rule, the contact sheets, and how the game picks a stem (so I know whether work stems need names like workshop_NN, hydroponics_NN, generator_NN, air_filter_NN, infirmary_NN, radio_NN).
6. Checks: bot_run, check_audience, check_save, check_network, check_slice must still pass. Commit the tool locally only: "Resident figures: fit tool". Do not commit incoming-art/.
