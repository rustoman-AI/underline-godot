CURSOR: CONTENT AUDIT AND RUN-TIME ESTIMATE (read-only, no gameplay changes)
Goal: real numbers for the Early Access plan (docs/EA_PLAN.md, section Gaps). Local only. No push. Do not change balance, the map, events or saves. New files only: a script under .tools/ and a report under docs/audit/.

1. COUNTS. From the data and the sim: events (by type: major, minor, check, with follow-up, with cooldown), choices per event (min / mean / max), laws, rooms and upgrades, seasons, artifacts, bunkers, endings, named characters, backstories, voiced lines, stations, tunnels, audience deals.
2. 40-WEEK REPEAT RATE. Run the bot for 30 seeds. For each run record: events shown per week (mean), distinct events shown, how many events appear twice or more, the longest gap without an event, weeks with zero decisions, and the number of player decisions per week (orders, laws, event choices, audiences). Report mean / min / max and the 5 weeks that are emptiest and the 5 busiest across seeds.
3. RUN-TIME ESTIMATE. Assume seconds per decision by type (event choice 25 s, order 12 s, law 30 s, audience 40 s, reading the dawn report 20 s, building/assigning 60 s per week). State the assumptions in the report. Estimate a new player's minutes per week and the 40-week total for a careful, a normal and a fast player.
4. DEAD ENDS. For each of the 30 bot seeds, list endings reached and how often; list events that never fire and choices never picked by any bot style (if the bot has several styles, use them all).
5. LEADER DEALS. How often the five leaders appear per run, how often each deal is accepted by each bot style, and what, if anything, changes in the game state 5 and 10 weeks after an accepted or refused deal (diff of flags, standing, journal rows). This shows where consequences are missing.
6. REPORT: docs/audit/content_audit_YYYYMMDD.md with tables and a short list of what looks thin. Do not propose design changes; only facts. Commit locally: "Content audit script and report". Checks must still pass.
